# 微信云开发部署

本项目使用云数据库、云函数和云存储。之前日志中的 Express/Docker 流水线不再使用；不要为本项目添加 Dockerfile。

代码已接入环境 `aihop-d6gxlq7zxdfdea087`（见 `miniprogram/app.ts`）。需要在微信开发者工具中确认这是 AppID `wxb2f1847429dac89a` 可访问的云开发环境；如使用其他环境，同时修改客户端初始化环境和云函数部署目标。

## 1. 初始化云数据库（只做一次）

在微信开发者工具中打开“云开发”，选择上述环境，创建集合 `activities`。将该集合的自定义安全规则设置为 [database.rules.json](../cloud/database.rules.json) 的内容，即禁止客户端直接读写。

在集合中添加 [activity.initial.json](../cloud/activity.initial.json) 的文档，ID 必须是字符串 `main`。使用 JSON 导入或添加文档均可。**已存在 main 文档时不要重新导入**，以免清空已有数据。云函数用服务端 SDK 访问这个集合，不受客户端读写规则限制。

## 2. 配置云存储

将云存储自定义安全规则设置为 [storage.rules.json](../cloud/storage.rules.json)：登录用户可读，仅文件创建者可写。不要配置为所有人可写。媒体上传路径为 `media/<当前用户openid>/<随机文件名>`；持久化保存的是 cloud 文件 ID，视频和预览图片在显示时换取临时链接。

移除图片、视频或更换头像只移除活动中的引用，不自动物理删除文件，避免误删被引用的资源。定期通过云控制台清理不再引用的历史文件；保存冲突或网络失败后上传的文件也可能成为未引用文件。

## 3. 部署云函数

项目已设置 `cloudfunctionRoot: cloudfunctions/`。在开发者工具中将 `cloudfunctions` 的云环境设为上述环境，对 `activity` 目录执行“上传并部署：云端安装依赖”。现有函数运行时为 `Nodejs16.13`（开发者工具默认创建，代码已兼容），超时 15 秒、内存 256 MB；这些非敏感配置已保存在根目录 `cloudbaserc.json`，管理员身份只保存在云函数环境变量中。

函数通过 `wx-server-sdk` 的 `getWXContext()` 获取微信身份，不信任客户端传入的身份或角色。不要配置无需鉴权的 HTTP 访问入口。

首次编译小程序将自动注册当前微信用户，默认角色为普通用户。在“我的”页面点击“复制我的 OpenID（用于授权）”，然后在**云函数 activity 的服务端环境变量**配置：

| 变量 | 内容 |
| --- | --- |
| `ADMIN_OPENIDS` | 管理员 OpenID，多个用英文逗号分隔 |
| `REFEREE_OPENIDS` | 裁判 OpenID，多个用英文逗号分隔 |

同一身份同时出现在两者中时，以管理员为准。环境变量必须按云平台要求保存并使新的函数配置生效，然后返回小程序点击“刷新”。不要将这些身份列表提交到 GitHub。普通用户不能自行切换身份，也不会因首个进入活动而自动成为管理员。

## 4. 建立正式活动

管理员创建队伍和项目，填写规则、时间、地址、地图坐标及 3D 标记。其他微信用户进入后各自填写姓名并选择微信头像并加入队伍；成员可退出队伍，队长可修改本队队名和头像，管理员可调配成员。队员可更新本队参赛状态，管理员和裁判可录入 0～100 分成绩，排行榜自动汇总。

旧版手机中的 `rally-demo-v1` 数据不会上传到云端，也不会作为新用户身份使用。正式环境从空活动开始，不自动加入演示成员。

## 5. 双设备验收后发布

1. 使用两个不同微信账号预览，确认姓名、头像和所属队伍各自独立。
2. A 填写姓名并加入队伍或修改资料，B 点击首页“刷新”看到变化。首页、项目页在可见时每 10 秒同步一次；网络失败时显示错误，不退回演示数据。
3. 普通用户没有编辑项目和评分入口；即使构造云函数请求，服务端也应拒绝越权修改。裁判能评分、不能改项目规则。
4. 两端基于同一版本修改时，只能一个保存成功；另一端提示“数据已被更新”，刷新后重新操作。不要自动覆盖或重复提交旧快照。
5. A 上传头像、图片、视频，B 能查看；真机确认地图授权、视频播放和 3D 展示。
6. 断网保存，确认提示失败且没有成功提示或提前跳页；恢复网络后刷新，云端值保持完整。
7. 在开发者工具“上传”，再到微信公众平台提交审核、发布。上传小程序代码不会部署云函数或设置数据库规则，前面的步骤必须先完成。

当前实现按单场活动共享一个事务文档，限制最多 300 名成员、60 支队伍、60 个项目和 700 KB 活动 JSON，适用于公司团建。并发冲突会显式拒绝，不会静默覆盖。媒体文件独立放在云存储中。如果要多场活动并行或大规模使用，需要按活动和记录拆分集合与权限。

## 资料与项目交互更新

用户通过微信 `chooseAvatar` 主动选择微信头像，姓名使用普通文本输入，由本人填写，不自动使用微信昵称。进入队伍前需填写姓名。队伍编辑提供按姓名搜索已注册用户的功能；管理员可在搜索结果中加入或移出成员，队长可搜索查看成员并编辑本队名称、头像。

项目详情包含“项目详情”和“队伍进度”两个 tab。队员在队伍进度中操作本队开始与完成，管理员、裁判不具有代改其他队伍进度的权限；评分权限保留。原项目整体状态仅作为旧数据兼容字段，由队伍进度汇总，不提供单独的操作入口。

地点编辑的按钮与字段统一为“搜索地点”“说明”“保存”，说明可空。旧的“请选择精确地点”提示会自动清除；项目资料表单仅保留名称和规则，地点通过地图页面修改，不再提供最下方的地址、计划时间编辑。

本次更新验证：17 项自动测试、TypeScript 严格检查通过；已通过微信开发者工具检查个人资料、队伍搜索、项目详情与队伍进度、地点页。真实云端临时项目验证了本队直接开始与完成、整体旧状态自动归一化、空说明保存；临时项目已清理，并与变更前备份比对，原有队伍、项目、成员、成绩与媒体保持一致（仅归一化旧默认文字和汇总状态）。微信头像选择仍需用户本人在真机点击授权。
